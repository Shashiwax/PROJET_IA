# RL-Based Inverter Sizing (SKY130A) — Usage Guide

This repository trains and evaluates agents to size a SKY130A inverter (parameters `wn`, `wp`) using SPICE-based metrics (area, delay, static power, dynamic energy) and logic constraints.

## Prerequisites

- **Python + uv**: this project is run via `uv run ...`
- **ngspice** installed and accessible in your PATH (`ngspice -v`)
- A working SKY130 setup / netlists that run correctly with ngspice.

Typical first-time setup:
```bash
uv sync

```

---

## Repository layout

* `src/inverter_env.py`: Gymnasium environment wrapping **one SPICE simulation per step**.
* `src/train_ppo_parallel.py`: PPO training (Stable-Baselines3 + parallel environments).
* `src/run_trained_ppo.py`: Deterministic evaluation of a trained PPO model (`.zip`).
* `src/train_cem_pool.py`: CEM (Cross-Entropy Method) training with parallel pool.
* `src/plot_cem.py`: Visualization tool for CEM convergence.
* `src/pools.py`: Worker pool logic for parallel SPICE simulations.
* `netlists/*.cir`: SPICE netlists with `.meas` metrics.
* `runs/`: Created automatically. Stores logs, models, and results per run.

---

## 1. PPO Training (Deep RL)

PPO learns a policy network to navigate the parameter space. It is ideal for complex, non-linear trade-offs.

### Quick Start

```bash
cd src
# Default run (creates runs/ppo/inv/tt/runXXX)
uv run python train_ppo_parallel.py

```

### Configuration (Environment Variables)

You can override defaults via env vars without changing code:

| Variable | Default | Description |
| --- | --- | --- |
| `N_ENVS` | `4` | Number of parallel SPICE workers |
| `TOTAL_TIMESTEPS` | `30000` | Total number of steps (budget) |
| `MAX_STEPS` | `6` | Steps per episode (retries allowed for the agent) |
| `N_STEPS` | `92` | Steps collected per worker before update |
| `BATCH_SIZE` | `92` | Minibatch size (should divide `N_ENVS * N_STEPS`) |

### Evaluation & Resume

* **Resume:** `uv run python train_ppo_parallel.py --run run004 --resume`
* **Evaluate:** `uv run python run_trained_ppo.py --run run004` (runs deterministic inference on the trained model).

## 2. CEM Training (Evolutionary Baseline)

CEM (Cross-Entropy Method) is a gradient-free algorithm. Instead of a neural network, it evolves a Gaussian distribution (Mean/StdDev) toward the optimal parameters by selecting the top performers ("elites") at each iteration.

### Quick Start

```bash
cd src
# Creates runs/cem/inv/tt/runXXX
uv run python train_cem_pool.py

```

### Run Folder Structure

CEM runs are organized exactly like PPO runs for consistency:

```text
runs/cem/<cell>/<corner>/runXYZ/
  config.json             # Metadata (hyperparams, seed)
  cem_history.csv         # Iteration logs (Mean, Std, Best Reward)
  best_point_metrics.csv  # Detailed SPICE metrics of the winner
  best_summary.json       # Concise summary of the best result
  cem_convergence_plot.png # Generated by plot_cem.py

```

### Key Parameters (in `train_cem_pool.py`)

* `n_iters`: Number of generations (e.g., 20).
* `batch_size`: Population size per generation (e.g., 96).
* `elite_frac`: Top % kept to update the distribution (e.g., 0.25).
* `W_BINS`: The algorithm "snaps" values to valid PDK grid steps.

## 3. Visualization & Analysis

### Plotting CEM Convergence

Use `plot_cem.py` to generate graphs showing how the parameters () and rewards evolve over time.

**Usage:**

```bash
cd src

# Automatically plot the latest run
uv run python plot_cem.py

# Plot a specific run
uv run python plot_cem.py --run run001

# Display interactively
uv run python plot_cem.py --show

```

**Output:** Saves a `cem_convergence_plot.png` inside the run folder.

### TensorBoard (PPO)

To view PPO training curves (Reward, Loss, Entropy):

```bash
tensorboard --logdir runs/ppo

```

## 4. Reward Configuration

Both algorithms share the same physics engine (`RewardConfig` in `inverter_env.py` / `pools.py`).
The global reward is a weighted sum of normalized costs:

$$ Reward = - ( w_{area} \cdot Area + w_{delay} \cdot Delay + w_{power} \cdot Power + \dots ) $$

To favor smaller designs over faster ones, increase `W_AREA` and `W_SIZE` via env vars or in the config dataclass.
